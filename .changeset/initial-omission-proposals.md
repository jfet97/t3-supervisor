A first proposal that leaves out a member of a flexible workflow now reaches the agent and can be agreed. Before, the Supervisor recorded it correctly but the service withheld it with "The interpreted proposal could not be confirmed from the Supervisor's recorded interpretation; the draft was not sent", because a stored copy listed the omission's fields in a different order. The check now compares the plan's actual values, so any real change to the plan is still refused. The Supervisor also receives much less repeated material: the definitions index is sent once instead of alongside a second copy, selected definitions arrive once each without the index or pre-expanded nested plans, the context view no longer repeats the index, the definitions reader no longer advertises a plan schema it never uses, and an interpretation request quotes each of the requester's messages once. The agent now receives a short notice instead of the whole proposal: it names the proposal and the project.yaml entry point, and the agent reads its complete current plan, including omissions, branches and the acceptance record, on demand with the new supervision_plan tool, which answers only for the agent's own current task and is refused for any other chat, an outdated or obsolete proposal (after the request was edited or the Supervisor was replaced) or a stopped chat. A revised proposal the Supervisor publishes is now delivered too: before, the service withheld its notice with the same "could not be confirmed" error and the agent could not agree it. The service now sends that notice itself, once, only after the revision is recorded, so the agent can read it immediately; the Supervisor no longer sends a notice of its own.
