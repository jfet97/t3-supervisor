Settlement now covers the complete participant set of a completed task: besides the main and its Supervisor, the main's lineage descendants and the local T3 conversations its contributions declared settle once per completed execution by their own automatic-settle command on the update time their fresh read showed, so T3 rejects the command atomically when the conversation changed or its user chose in between; a conversation in a linked environment has no supported route and is listed unsupported without a command. A reserved command never changes: a lost reply is retried with the same payload at most three times, no second command is reserved while its outcome is unknown, on that or any later execution, and only a settled read, later native activity, the user's choice or a definite rejection resolves it, with the command kept in the record. Each command is admitted only while the same execution is still complete and the participant still a member. An execution is the task, its scope revision and the main document's latest completion record, so the next task, or the same task completed again after a return, evaluates every participant anew while the earlier rows stay as history; the progress page shows the current execution's rows on any workflow page. Intermediate review rounds never settle a reviewer, and participants that are not T3 conversations are shown as not applicable. In History, each earlier review attempt is headed by its target and time instead of a return count that is not the occurrence's attempt.
