Supervisors and helpers now receive much shorter messages and read the rules and context they need on demand. Every message to a Supervisor names its task and the version of its instructions instead of repeating the full role; the instructions are read once as a short core with sections, and interpretation rules are read in two stages so a quick request no longer loads the whole planning manual. Check-ins, protocol repairs, definition reviews, helper check-ins, team notifications and planning holds carry identities and codes, and team, guidance and planning answers return only the action's own result. Every message they point to is named by the exact item T3 reads it by, so a Supervisor, helper or planning writer can open the request, the user's messages or a draft result directly, and a message that is not yet readable that way is found by paging the conversation. A planning writer can read the current intent, the current plan with its task-local duties and the shared plan grammar itself, before and after it is attached, without seeing the root's own submission details. The operative's proposal notice is a short event with the exact call that returns the complete proposal. Stop notices, status reads and other answers are shorter, while every authority, Stop and approval rule still applies. Instructions name tools by operation and no longer describe a particular gateway.
